# 拾流 · 网页影音下载器

为桌面版 Chrome 和 Edge 识别当前标签页中的视频、音频和播放清单。支持保存普通媒体文件，将独立视频和音轨无损合并为 MP4，也能为未加密的 HLS 点播选择画质或音轨。HLS 逐片写入本地，单个输出文件最大 **4 GiB**。

**[下载拾流 1.3.2 安装包](./Shiliu-1.3.2.zip?raw=true)**

1.3.2 的 MP4 视频入口会自动检查文件是否带声音：已有声轨直接保存，画面与声音分离时自动寻找同一视频的配套音轨并合并。还修复了切换页面后的旧资源回流、跨框架配对、音频延时、大文件偏移、HLS 时长和异常文件检查问题。

## 安装

1. 将安装包解压到准备长期保留的文件夹。使用本仓库源码时，直接选择 `extension` 文件夹即可。
2. 在 Chrome 打开 `chrome://extensions/`，在 Edge 打开 `edge://extensions/`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。

升级时，将新版覆盖到原目录，在扩展管理页点击拾流卡片上的「重新加载」。两个浏览器需分别重新加载。

## 下载

在目标网页播放几秒，打开拾流，按类型筛选资源。

| 资源 | 操作 |
| --- | --- |
| WebM、MP3、M4A 等其他媒体文件 | 点击「下载」。如果拾流打开了新页，在新页选择保存位置并查看进度。其余文件在浏览器下载记录中查看。 |
| MP4 视频，包括画面与声音分离的资源 | 点击「下载视频」，选择保存位置。拾流自动检查实际轨道，已有声音则直接保存，只有画面则自动寻找并合并配套音轨。无需手动选择两个文件。 |
| HLS 点播（M3U8） | 点击「HLS 下载」，选择画质或音轨，再点「选择位置并下载」。保持下载页打开到显示「已保存」。 |
| DASH（MPD） | 「保存清单」会得到描述轨道和分片地址的 MPD 文件。 |

HLS 每次导出一个轨道。如果网站把声音和画面分开，需要分别保存。支持常见的 MPEG-TS、带初始化片段的 fMP4、AAC 和 MP3。直播、加密清单和 DRM 内容超出本版支持范围。

### 音画分离的 MP4

1.3.1 支持普通 MP4、分片 MP4，以及两种格式混合的独立音视频轨道，无需安装 FFmpeg，也不重新编码。合并结果统一保存为带完整索引的普通 MP4，修复 1.3.0 部分输出在 Windows 媒体播放器中提示不支持编码、无法读取的问题。

下载页先读取两个源文件到浏览器临时存储，检查实际轨道和时长，再合并保存。完成或取消后清理本次临时文件；意外关闭浏览器可能留下临时数据。

自动配对使用同一播放器文档中的内容标识，以及抖音同一视频记录内明确列出的画面和完整音轨地址；不会把背景音乐当作视频原声。多个画质可以使用同一配套音轨。缺少可靠关联或存在歧义时会明确提示回原网页播放目标视频后重新扫描，不会猜配音轨或把无声文件当成有声视频保存。若确实只需要原始文件，可点击「下载原文件」；独立音频仍可从「音频」筛选查看。

支持常见 H.264、HEVC、AV1 视频与 AAC 等 MP4 音轨；实际播放兼容性取决于播放器。加密轨道、单个分片含多轨道、缺少必要偏移信息的特殊分片、需要转码的输入以及直接解析 MPD 后下载分片不属于本次合并支持范围。媒体内容只在本机处理。

对解码时间存在间隙或非零起点、含负组合时间偏移的特殊分片，合并页会明确报错，避免生成错位的音画。输出索引上限为 32 MiB。合并页也会明确拒绝暂不支持的 `stz2` 紧凑样本表、无法精确表示的共同电影时间基准，以及超过解析复杂度或样本数量上限的输入。

若出现 HTTP 401、403 或 412，请确认原网页还能播放，再刷新网页、播放几秒、重新扫描。升级后也请刷新播放器所在网页，让拾流记录一次成功的媒体请求。列表里同时出现 master.m3u8 和 index 开头的清单时，先打开 master.m3u8。若服务器拒绝主清单，可改用同一目录中已发现的画质清单。

## 权限与数据

拾流在本机读取 HTTP 和 HTTPS 媒体请求的响应类型、文件名和长度，并在打开面板或重新扫描时检查网页中的播放器。跨域播放器和 CDN 也需要相应的网站访问权限。资源清单在浏览器会话中按标签页暂存，下载直接访问源站。

为关联抖音动态加载的独立音轨，拾流会在该网页中观察已经收到的视频接口响应，只保留媒体地址及配对所需的内容标识，不额外请求接口，也不记录完整响应、Cookie 或认证信息。升级后请刷新原网页，让观察器从页面加载时开始工作。

有些媒体服务器会核对请求来自哪个网站。下载页可向同一媒体源重用播放器成功请求的来源站点（Origin、Referer）。该临时规则仅对当前下载标签页生效。若原请求携带 Cookie，下载页可向该媒体源请求使用浏览器现有会话。扩展只记录是否携带 Cookie，不保存其值。

如果播放器在扩展加载前已经访问了 HLS 清单，打开下载页时，拾流可在原播放器所在文档中匿名重新读取该清单，以恢复来源信息。这次检查只访问网页已请求的同一地址，并遵守该网页和媒体服务器的跨域访问设置。

## 测试

使用 Node.js 24 或更新版本，在仓库根目录运行 `node --test tests/*.test.cjs tests/*.test.mjs`。媒体测试还需要 FFmpeg 和 ffprobe；缺少时会显示跳过，不能视为完整验证。安装和使用扩展只需浏览器。

安装 FFmpeg 和 ffprobe 后，可运行 `node tests/browser-context.mjs "<浏览器可执行文件路径>"`。该测试使用临时浏览器配置和本地测试服务器，生成带画面与声音的 HLS 视频、从拾流面板下载并解码校验。

运行 `node tests/browser-merge.mjs "<浏览器可执行文件路径>"` 可验证独立视频与分片音频的配对、下载、合并、完整解码及取消流程，并检查浏览器实际播放、跳转和播放结束。所有浏览器测试使用独立临时配置，不操作个人浏览记录；测试媒体由 FFmpeg 生成并由本机服务器提供。

合并测试还覆盖已有声轨原样保存、缺少或歧义关联时停止、取消写入后保留旧文件。添加 `--page-json` 验证无 URL 内容标识的页面数据配对；添加 `--page-observer` 验证页面加载后首次 Fetch 响应的自动关联，配合 `--observer-xhr` 则验证 XHR。对应站点名仅在独立测试浏览器中映射到本机夹具，不访问真实账号。`--fragment-video --ordinary-audio` 用于交叉验证另一种普通/分片组合。

Windows 上还会调用 `tests/native-playback.ps1`，使用 Media Foundation 将视频解码为 NV12、音频解码为 PCM，并检查最终时长和接近结尾处的跳转；MP4 合并与 HLS fMP4 导出均纳入检查，防止仅 FFmpeg 能读而系统播放器不能正常读取的回归。
